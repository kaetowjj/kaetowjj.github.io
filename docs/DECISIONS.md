# Development decisions

These records describe choices established in the repository and prior owner requests. Commit links identify where the behavior landed. Reasons are recorded when supported by the conversation or repository history.

| Decision | Reason and convention |
| --- | --- |
| Keep the site static. | The original project uses Jekyll, local collections/data files and GitHub Pages. Node is for image processing and validation. Authoring goes through Git, with no upload service or database. Preserve sitemap and basic SEO. See [requirements V2](requirements-v2.md) and the [initial site](https://github.com/kaetowjj/kaetowjj.github.io/commit/41eca14). |
| Keep Chinese and English in one document and URL. | Article front matter has paired title/description fields, and one Markdown file holds both bodies. This keeps translations together and lets readers switch in place while preserving a single canonical URL. Use `markdown="1"`, blank lines and available-language fallback. The article TOC follows the visible language. See [publishing](publishing.md). |
| Combine Notes and Projects into Tech Blog. | The owner chose to organize technical writing as one archive with tags. New technical articles go in `_tech/`, optional tags derive from front matter, and archive filters can be shared via the URL. Essays remain separate. See the [Tech Blog change](https://github.com/kaetowjj/kaetowjj.github.io/commit/9a3ff4c). |
| Keep Home short and put longer personal writing on About. | The home page gives readers a short introduction and routes into the site. About retains the full bilingual Exploring and Beyond Engineering paragraphs. Recent Posts combines technical articles and essays, excludes Demo content, and ranks by the original publication date. See the [Home/About change](https://github.com/kaetowjj/kaetowjj.github.io/commit/9fcf6d9). |
| Use a shared, restrained theme and consistent link states. | The owner specified Light/Dark/System, warm-orange light and sage-green dark hover colors, a visible focus outline, and a stable current-nav underline. Decorative diagonal arrows use SVG with `currentColor` to avoid iOS emoji rendering. The About avatar crops responsively and falls back to initials. Contact details are data-driven, with a public email alias. See [hover states](https://github.com/kaetowjj/kaetowjj.github.io/commit/0fc622f), [link arrows](https://github.com/kaetowjj/kaetowjj.github.io/commit/9a3ff4c), and [avatar](https://github.com/kaetowjj/kaetowjj.github.io/commit/71d1775). |
| Preserve photo proportions and use stable taxonomy IDs. | Equal visual priority and capture-date ordering were project requirements. Lowercase kebab-case IDs are separate from bilingual display labels. Validation catches invalid references. Originals stay outside published assets, Sharp strips EXIF/GPS, and the owner reviews and merges the generated import records manually. See [taxonomy cleanup](https://github.com/kaetowjj/kaetowjj.github.io/commit/94285c2) and [photography](photography.md). |
| Reuse one Dot Wave inside existing heading space. | The owner chose abstract dotted terrain with shared geometry across themes, a warm daylight palette and a silver-green night palette. Heading waves reuse available space without a new banner. Keep the chosen double gust, 2× wind strength and 1.5× speed, with visibility and reduced-motion behavior. See [wave tuning](https://github.com/kaetowjj/kaetowjj.github.io/commit/c293f65) and [heading reuse](https://github.com/kaetowjj/kaetowjj.github.io/commit/9adb566). |
| Keep curated jokes in the Footer alone. | The owner first added a collection of real wordplay with source information, then chose to remove Home's duplicate display and Shuffle. Keep the original language, optional attribution and source URL. The Footer selects one entry on page load. See [Footer layout](https://github.com/kaetowjj/kaetowjj.github.io/commit/35001d4), [Footer-only change](https://github.com/kaetowjj/kaetowjj.github.io/commit/64a8f74), and [collection guide](silly-thoughts.md). |
| Use focused owner manuals. | The owner asked to keep README as the entry and move detailed operations into one primary document per topic. Preserve earlier requirements, test records and templates for context. See the [documentation split](https://github.com/kaetowjj/kaetowjj.github.io/commit/dd63f14). |

## Workflow decision introduced in this setup

Project-scoped Codex role files carry the six persistent role definitions. `AGENTS.md` owns delegation and file-ownership rules, and the primary Coordinator owns `progress.json`. The project leaves model selection to Codex. A spawn request or configured subagent default can choose the model, with the parent model as the fallback. Subagents inherit the parent session's permissions. This implements the current owner request. The four-subagent cap is a project default for keeping concurrent work manageable. Role definitions and progress are excluded from the published site.

## Production publishing

The confirmed GitHub Pages migration made GitHub Actions the sole authorized production publisher. The repository workflow builds and tests the site, then deploys the same tested artifact. This removes the competing branch publisher that could publish without the project checks. Use the custom workflow for recovery as well. See the [migration record](PAGES-MIGRATION.md) and [approval policy](../AGENTS.md).
